# Supabase + Prisma Persistence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Store user accounts and product data (catalog + price books) in Supabase Postgres through Prisma, with real sign-in, while Sales Reports, calculations and generated workbooks stay in memory and are never stored.

**Architecture:** The pure domain rules move from `frontend/src/app/domain/` to `shared/domain/` so the NestJS API and the Angular app run the same validation. Every API write takes a Postgres advisory lock in one transaction, loads the current rows, runs the existing pure domain function, and writes only what changed. The Angular services keep their `users` / `books` / `products` signals but load and save through the API with a bearer token held in memory.

**Tech Stack:** Prisma 7.10.1 (`prisma`, `@prisma/client`, `@prisma/adapter-pg`), `pg`, `dotenv`, `bcryptjs` 3, `jsonwebtoken`, zod 3 (existing), NestJS 11, Angular 21, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-26-supabase-prisma-persistence-design.md`

## Global Constraints

- Only four tables: `users`, `products`, `price_books`, `price_book_entries` (plus Prisma's `_prisma_migrations`). Nothing from a Sales Report, a calculation, a Needs Review row, a generated workbook, a ZenPOS file or the bank-rate configuration is stored or logged.
- No `@supabase/server` or `@supabase/supabase-js`; the database is reached only through Prisma with the Postgres connection strings.
- Prisma packages pinned to exactly `7.10.1`. Generator: `provider = "prisma-client"`, `output = "../src/generated/prisma"`, `moduleFormat = "cjs"`, `importFileExtension = ""` (verified: required for `node dist/...`). `backend/src/generated/` is gitignored and regenerated by `postinstall` and `build`.
- Env vars (`backend/.env`, gitignored): `DATABASE_URL` (transaction pooler, 6543, runtime), `DIRECT_URL` (session pooler or direct, 5432, Prisma CLI and scripts), `AUTH_SECRET` (≥ 32 characters), `TEST_DATABASE_URL`, `TEST_DIRECT_URL`. Credentials never appear in chat, commits or logs.
- Tests use a separate **`test` schema in the same Supabase project**: `TEST_DATABASE_URL` / `TEST_DIRECT_URL` are the real URLs with `schema=test` added (the controller writes them into `.env`; the user does not). The real `public` tables are never touched before Task 7.
- A connection string may carry `schema=<name>`. `createPrismaClient` passes it to `new PrismaPg({ connectionString }, { schema })` and removes it from the string handed to `pg`; the Prisma CLI reads it from the URL itself. Data is only ever deleted through Prisma-generated queries (always schema-qualified) — never raw SQL — and test setup only runs `prisma migrate deploy`, never `migrate reset`.
- Any script or test that deletes data uses only `TEST_*` URLs and refuses to run unless both are set, both name a `schema` other than `public`, and neither equals `DATABASE_URL` / `DIRECT_URL`.
- Money: `Decimal(12,2)` in the database ↔ JS numbers with ≤ 2 decimals at the API. Calendar dates: `@db.Date` ↔ `YYYY-MM-DD` built from UTC parts. Timestamps: ISO strings with milliseconds. Product IDs are always text.
- Every write runs in `prisma.$transaction(fn, { maxWait: 10_000, timeout: 30_000 })` and first takes `pg_advisory_xact_lock` (users `41001`, pricing `41002`).
- Error messages from `shared/domain/*` are returned verbatim. New fixed messages: 401 `Sign in again to continue.`; 403 per permission: calculator `You do not have permission to use the bank rate calculator.`, price-books `You do not have permission to manage price books.`, users `You do not have permission to manage user accounts.`
- Request/response shapes and logic of `/api/excel/*` and `/api/config/*` do not change.
- Passwords: bcrypt cost 12. Tokens: HS256, `sub` = user id, 12 h expiry. Token stored in browser memory only.

## Review Focus

- **A calendar date read back by a server running in Asia/Manila (UTC+8)** must not move a day (`2026-11-30` stays `2026-11-30`). Pinned by the Task 2 DB test `a calendar date round-trips without shifting` and the mapper unit test.
- **Transferring Accounting Head** must not trip the one-holder unique index: demote the previous holder before promoting the new one. Pinned by the Task 4 DB test `transfer survives the one-holder index`.
- **A price book edited in a tab opened before someone else saved it** must be refused with the 409 message and keep the draft, not overwrite the newer save. Pinned by the Task 5 DB test `a stale edit is refused` and the Task 6 e2e test `a stale edit is refused and keeps the draft`.
- **Calculate pressed while price books are still loading or failed to load** must not silently drop Supplier Support: it waits, and on failure shows the load error instead of results. Pinned by the Task 6 e2e test `price books that cannot be loaded are reported and calculation waits`.
- **An account deactivated mid-session** is refused on its next request and lands on the sign-in page. Pinned by the Task 3 unit test `an inactive account's token is refused` and the Task 4 e2e test `a deactivated user is signed out on their next request`.

```prisma
// Only user accounts and product data (catalog + price books) are stored here.
// Sales Reports, calculation results and generated workbooks are never stored.

generator client {
  provider            = "prisma-client"
  output              = "../src/generated/prisma"
  moduleFormat        = "cjs"
  importFileExtension = ""
}

datasource db {
  provider = "postgresql"
}

/// Role is 'admin' | 'accounting-head' | 'product-team' (CHECK constraint in the migration).
/// Usernames are unique case-insensitively and only one row may hold 'accounting-head'
/// (expression and partial unique indexes in the migration).
model User {
  id           String   @id
  username     String
  displayName  String   @map("display_name")
  passwordHash String   @map("password_hash")
  role         String
  active       Boolean  @default(true)
  createdAt    DateTime @default(now()) @map("created_at") @db.Timestamptz(3)
  updatedAt    DateTime @updatedAt @map("updated_at") @db.Timestamptz(3)

  @@map("users")
}

/// Product IDs are text: barcodes keep every digit and leading zeros.
model Product {
  id              String   @id
  name            String
  unit            String
  onHand          Int?     @map("on_hand")
  masterListPrice Decimal  @map("master_list_price") @db.Decimal(12, 2)
  sellingPrice    Decimal  @map("selling_price") @db.Decimal(12, 2)
  cost            Decimal? @db.Decimal(12, 2)
  /// 'demo' | 'import'; null when the source was not recorded.
  source          String?

  @@map("products")
}

/// id is the POS Price ID (PL/PS/PI + 6 digits, CHECK in the migration).
/// Names are unique case-insensitively (expression index in the migration).
model PriceBook {
  id             String           @id
  name           String
  description    String           @default("")
  effectiveDate  DateTime         @map("effective_date") @db.Date
  expirationDate DateTime?        @map("expiration_date") @db.Date
  active         Boolean
  updatedAt      DateTime         @map("updated_at") @db.Timestamptz(3)
  updatedBy      String           @map("updated_by")
  entries        PriceBookEntry[]

  @@map("price_books")
}

/// One product row of a price book, in display order. productId is not a foreign key:
/// ZenPOS and manual rows are not in the catalog. The manual_* columns are all null
/// (catalog row) or all set except manual_to_qty (CHECK in the migration).
model PriceBookEntry {
  priceBookId           String    @map("price_book_id")
  position              Int
  productId             String    @map("product_id")
  updatedPrice          Decimal?  @map("updated_price") @db.Decimal(12, 2)
  promoPrice            Decimal?  @map("promo_price") @db.Decimal(12, 2)
  effectiveStart        DateTime  @map("effective_start") @db.Date
  effectiveEnd          DateTime? @map("effective_end") @db.Date
  memo                  String    @default("")
  /// Supplier Support, pesos per unit; PS books only.
  support               Decimal?  @db.Decimal(12, 2)
  manualName            String?   @map("manual_name")
  manualQty             Float?    @map("manual_qty")
  manualToQty           Float?    @map("manual_to_qty")
  manualUnit            String?   @map("manual_unit")
  manualMasterListPrice Decimal?  @map("manual_master_list_price") @db.Decimal(12, 2)
  manualUnitPrice       Decimal?  @map("manual_unit_price") @db.Decimal(12, 2)
  manualDiscountPercent Decimal?  @map("manual_discount_percent") @db.Decimal(5, 2)
  manualDiscount        Decimal?  @map("manual_discount") @db.Decimal(12, 2)
  manualNetPrice        Decimal?  @map("manual_net_price") @db.Decimal(12, 2)
  manualCost            Decimal?  @map("manual_cost") @db.Decimal(12, 2)
  priceBook             PriceBook @relation(fields: [priceBookId], references: [id], onDelete: Cascade)

  @@id([priceBookId, position])
  @@map("price_book_entries")
}
```

```sql
-- ---------------------------------------------------------------------------------------------
-- Hand-written: rules Prisma does not model.
-- ---------------------------------------------------------------------------------------------

ALTER TABLE "users" ADD CONSTRAINT "users_role_check"
  CHECK ("role" IN ('admin', 'accounting-head', 'product-team'));
ALTER TABLE "products" ADD CONSTRAINT "products_source_check"
  CHECK ("source" IS NULL OR "source" IN ('demo', 'import'));
ALTER TABLE "price_books" ADD CONSTRAINT "price_books_id_check"
  CHECK ("id" ~ '^(PL|PS|PI)[0-9]{6}$');
ALTER TABLE "price_books" ADD CONSTRAINT "price_books_name_check"
  CHECK (char_length("name") BETWEEN 1 AND 80);
-- Supplier Support only exists on PS (external promotion) price books.
ALTER TABLE "price_book_entries" ADD CONSTRAINT "price_book_entries_support_check"
  CHECK ("support" IS NULL OR "price_book_id" LIKE 'PS%');
-- Manual/ZenPOS product details are all present or all absent (to Qty is optional).
ALTER TABLE "price_book_entries" ADD CONSTRAINT "price_book_entries_manual_check"
  CHECK (num_nonnulls("manual_name", "manual_qty", "manual_unit", "manual_master_list_price",
    "manual_unit_price", "manual_discount_percent", "manual_discount", "manual_net_price",
    "manual_cost") IN (0, 9)
    AND ("manual_to_qty" IS NULL OR "manual_name" IS NOT NULL));

CREATE UNIQUE INDEX "users_username_lower_key" ON "users" (lower("username"));
CREATE UNIQUE INDEX "users_one_accounting_head_key" ON "users" ("role")
  WHERE "role" = 'accounting-head';
CREATE UNIQUE INDEX "price_books_name_lower_key" ON "price_books" (lower("name"));
CREATE UNIQUE INDEX "price_book_entries_book_product_key"
  ON "price_book_entries" ("price_book_id", upper("product_id"));

-- Supabase exposes "public" through its Data API. RLS with no policies denies the anon and
-- authenticated keys; Prisma connects as the table owner, which RLS does not restrict.
ALTER TABLE "users" ENABLE ROW LEVEL SECURITY;
ALTER TABLE "products" ENABLE ROW LEVEL SECURITY;
ALTER TABLE "price_books" ENABLE ROW LEVEL SECURITY;
ALTER TABLE "price_book_entries" ENABLE ROW LEVEL SECURITY;
```
